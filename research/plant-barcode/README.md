# 프라이머 점수, 바코드 검출률, 종 구별력은 같은가?

공개 벼과 식물 엽록체만 사용한 `rbcL` 파일럿. [종별 결과를 보는 오프라인 화면](results/viewer.html), [정확 일치](results/summary.csv), [불일치 민감도](results/sensitivity.csv). 화면은 분석 결과 탐색용이지 FASTQ 분석기나 PCR 성공률 예측기가 아니다.

**대상과 분리:** NCBI Nucleotide에서 벼과 12개 속별로 `genus[Organism] AND chloroplast[Title] AND complete genome[Title] AND refseq[filter]`를 검색, accession 정렬 후 최대 10개씩과 벼 NC_001320.1을 포함했다. 전체 RefSeq 대표성 표본이 아니다. 60개 버전 지정 accession 중 이명법 이름으로 처리 가능한 58개 레코드, 종당 가장 낮은 accession 하나를 취해 53개 이름이 남았다. 6속 37종에서만 후보 선택; 설계에 포함하지 않은 5속 16종에서 한 번 평가. Festuca 질의에서 레코드가 없어 12번째 속은 평가되지 않았다. 속 전체를 분리했지만 한 고정 패널이며 종내 변이, 핵·미토콘드리아 오프타깃, 동정 오류는 평가하지 않았다.

**실제 설계:** 벼 레퍼런스의 주석된 rbcL CDS를 읽고 여러 창에서 Primer3로 서로 다른 76쌍을 생성. ① 열역학 페널티 최저 후보, ② 설계 패널에서 구별되는 종 수, 이어 검출 종 수, 페널티 순으로 택한 후보, ③ [공개 벼과 rbcL 프라이머](https://doi.org/10.3389/fpls.2022.998863)를 비교했다. ③은 기존의 다른 길이 바코드이므로 길이·위치·설계 알고리즘 효과를 분리하는 대조가 아니다.

각 원형 엽록체의 양 가닥에서 80–1600 bp 이내 산물이 하나이고 내부에 모호한 염기가 없을 때 검출로 분류한다. 프라이머 부분을 제거한 내부 서열이 그 평가군의 다른 검출 종과 일치하지 않으면 '구별'로 센다. 이는 이상적 참조 서열의 **패널 내 고유성**이지 미지 시료 분류 정확도나 민감도가 아니다. 정확 일치와 프라이머 각각 1개 불일치 허용 조건을 별도로 계산했다. 불일치 위치와 실제 결합 효율을 동일시하면 안 된다.

| 설계에서 제외한 16종 | 정확 일치: 검출 / 고유 | 불일치 허용: 검출 / 고유 |
|---|---:|---:|
| Primer3 점수만 | 0 / 0 | 9 / 3 |
| 패널에서 고른 후보 | 6 / 4 | 15 / 10 |
| 발표된 풀과 프라이머 | 7 / 4 | 14 / 11 |

**판단:** 프라이머 후보 자동 생성과 검출률 보고는 가능하지만 새 후보가 기존 프라이머보다 종을 더 잘 구별한다는 근거는 없다. 매칭 기준 하나로 결론이 달라진다. [Primer-BLAST](https://doi.org/10.1186/1471-2105-13-134), [PrimerEvalPy](https://doi.org/10.1186/s12859-024-05805-7)도 이미 있다. 좋은 방법 논문이 되려면 공개된 독립 실험의 검출/미검출을 사전 고정한 점수가 얼마나 예측하는지, 단순 규칙·기존 도구와 같은 표본에서 비교해야 한다. 이 식물 파일럿은 16S/ITS에 대한 검증이 아니다.

재현: Python 환경에 `pip install -r requirements.txt` 후 아래 실행. 원본은 캐시 밖에 배포하지 않는다. NCBI가 같은 accession 버전의 GenBank 주석을 갱신해 체크섬이 달라지면 자동 통과시키지 않고 중단한다.

```sh
CACHE="$HOME/tmp/celllab-grass-barcodes"
python run.py "$CACHE" results
python sensitivity.py "$CACHE" results
python report.py
```
